# 项目记忆

## 长期背景

- GitHub 仓库已经创建并克隆到本地。
- 本项目用于实现企业微信会话内容存档集成。
- 已确定使用 Python 3.10 作为开发与运行版本，并使用 uv 管理项目环境、依赖和锁定文件。
- 用户希望先制定计划并建立项目记忆，再开始编写业务代码。

## 当前状态

- 已初始化仓库协作约定、计划、架构、决策和项目记忆文档。
- 已建立 Python 包骨架，并完成 `CustomerContactDirectory` 的首个可运行版本；测试套件直接调用真实企业微信 API，等待使用非生产企业账号完成首次联调。
- 已明确三个功能阶段：客户联系资料同步、会话存档及附件同步、可配置的消息处理管线。
- 最终以可安装、开箱即用的 Python 包交付，并允许其他 Python 程序集成。
- 首版不提供命令行工具；`WeComArchive` 是会话存档主类，独立公共组件 `CustomerContactDirectory` 负责客户、客户群和群成员资料同步与查询。
- `CustomerContactDirectory` 提供整体和分类单次同步入口，内部拆分客户同步、客户群同步和资料仓储；其具体 API 调用流程需在实现前查阅企业微信官方文档。
- 客户联系资料首版只支持企业内部自建应用，通过企业 `corp_id` 和“客户联系 Secret”认证；第三方服务商授权模式后续再扩展。
- 首个交付里程碑是完成客户、跟进关系、客户群、群成员和群管理员的可恢复全量同步；完整扫描后仅软标记本轮未见资料，不物理删除。
- 会话消息始终保存原始成员 ID、客户 ID 和群 ID，并在查询或处理阶段关联本地资料目录；资料暂缺或同步失败不得阻塞会话归档。
- `WeComArchive` 初始化时必须传入企业微信会话存档凭据，数据库配置可选；它不提供 HTTP 服务，也不使用 httpx，会话拉取、解密和附件下载均通过企业微信会话存档 SDK 完成。
- `CustomerContactDirectory` 使用 httpx 调用客户和客户群 REST API，独立管理相关凭据及可选 HTTP 代理；异步数据流优先使用 `httpx.AsyncClient`。
- 持久化层统一使用 SQLAlchemy 2.x ORM 和 Alembic，首版支持 SQLite、MySQL 和 PostgreSQL；未配置数据库时自动使用 SQLite，但不绕过 ORM。
- `WeComArchive` 采用长期运行模型，在初始化和注册处理器后按配置间隔持续轮询新消息；外部系统只负责启动、守护和重启进程。
- 长期运行入口为阻塞式 `run_forever()`，程序内可调用 `stop()` 请求优雅退出并释放资源。
- 优雅停止会等待当前消息完成持久化和本轮处理器调用，不再开始下一轮轮询。
- 已确定原始消息先持久化，再运行第一版进程内处理器；正式插件机制后续按需演进。
- 用户通过可重复调用的 `register_handler` 注册多个消息处理函数，处理函数按注册顺序执行。
- 处理器名称可显式指定，默认由函数模块名和限定名生成；名称必须唯一，冲突在运行前报错。
- 同一消息的处理器按注册顺序执行，不同消息可并行，默认最多并行处理四条消息并允许初始化时配置。
- 每个处理函数接收只读 `Message`，它薄封装企业微信官方消息结构并完整保留原始解密数据，不另建自定义消息协议。
- 处理函数采用独立事件监听语义：接收同一消息、返回值忽略，函数内部自行过滤，不影响其他监听器。
- 处理器失败相互隔离，不回滚消息或游标；失败项跨同步调用退避重试，默认最多三次，之后进入等待人工处理的最终失败状态。
- `run_forever()` 内部使用 asyncio 调度；异步处理函数作为协程运行，同步处理函数进入受限线程池，首版不支持多进程处理器。
- 同步处理函数的超时与取消语义暂缓决定；线程无法被安全强制终止，是否增加取消上下文仍待确认。
- 首版以数据库租约队列持久化处理任务，不依赖外部消息代理；任务支持原子领取、租约到期恢复、唯一约束和状态重试。
- 附件二进制内容使用可插拔存储后端，关系数据库保存附件元数据和稳定存储引用；默认使用本地文件存储，可在初始化时传入第三方存储对象替换。
- 首版只内置本地文件存储，不内置第三方对象存储适配器。
- 尚未确定附件写入与数据库事务的一致性策略和部署方式。
- 已实现客户和客户群的分页全量同步、SQLAlchemy 持久化、Alembic 自动迁移、本地只读查询、失败扫描保护和敏感信息脱敏；不再保留模拟企业微信响应的测试。
- 客户联系内部自建应用鉴权已封装为独立的 `httpx.Auth` 实现，同时支持同步与异步认证流，集中负责访问令牌缓存、并发刷新和令牌失效后的单次请求重放；`WeComCustomerClient` 保留同步 API，并提供对应的 `async_*` API 和 `aclose()`。

## 下次讨论重点
