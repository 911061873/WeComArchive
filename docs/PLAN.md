## 建议里程碑

### 首个交付里程碑：客户联系资料目录

范围：

- 仅支持企业内部自建应用，不包含第三方服务商授权模式。
- 提供 `CustomerContactDirectory`，支持单次同步全部资料、仅同步客户、仅同步客户群。
- 同步客户、客户与跟进成员关系、客户群、群成员和群管理员，并保留企业微信返回的原始 JSON。
- 通过异步 `httpx.AsyncClient` 统一处理访问令牌、超时、可选 HTTP 代理、请求重试和企业微信错误响应。
- 使用 SQLAlchemy 2.x 异步持久化，默认 SQLite，模型保持 MySQL 和 PostgreSQL 兼容。
- 每次同步记录独立运行状态；只有完整扫描成功后才能提交“本轮未见”状态，禁止用不完整结果清理已有资料。

验收标准：

- 多页客户或客户群响应能够完整同步。
- 相同数据重复同步不会产生重复记录，资料变化能够更新。
- 同一客户由多个成员跟进时，所有跟进关系均可保存和查询。
- 群成员变化后本地关系能够更新；本轮未见的数据只做软状态标记，不物理删除。
- 任一分页或详情请求失败时，本次运行标记为失败，且不把未完成快照当作成功结果。
- 日志和公开异常不包含 Secret、访问令牌或代理认证信息。
- 集成测试直接调用真实企业微信 API；凭据只通过环境变量注入，缺少非生产凭据时测试跳过。

## 已知性能与异步边界

- 客户同步已经支持成员分组有限并发和客户批量事务写入；客户群列表、群详情和群关系写入仍为串行流程。
- `sync_all_once()` 仍先完整执行客户同步，再执行客户群同步，并且两个流程分别获取一次配置了客户联系功能的成员列表。
- SQLAlchemy 数据库访问使用异步驱动，但 Alembic 的 `command.upgrade()` 通过同步回调执行；迁移控制逻辑并未整体卸载到工作线程。
- 默认 SQLite 使用 `aiosqlite` 将同步 SQLite 操作放到工作线程，对事件循环是可等待的，但不等同于原生异步数据库，也不适合通过增加并发写任务提升吞吐。
- HTTP 响应 JSON 解析、Pydantic 校验、模型序列化、深拷贝和公开对象组装属于同步 CPU 工作，目前直接运行在事件循环线程；优化前应先用真实数据测量耗时。
- 默认数据目录的 `resolve()` 和 `mkdir()` 当前在 `CustomerContactDirectory` 普通构造函数中同步执行。

## 已明确的功能范围

1. 通过独立的 `CustomerContactDirectory` 同步客户、客户群及群成员资料，并提供本地查询能力，不与会话存档主类混合。
2. `WeComArchive` 增量拉取企业微信会话存档，解密消息，下载音频、文件等附件并默认持久化。
3. 用户可以在初始化后通过注册方法向 `WeComArchive` 添加消息处理函数。
4. `WeComArchive` 提供长期运行方法，按照初始化时配置的轮询间隔持续拉取新消息。
5. 首版不提供命令行工具；会话存档通过 `WeComArchive` 类使用，客户联系资料通过 `CustomerContactDirectory` 同步和查询。
6. 初始化 `WeComArchive` 时必须提供企业微信会话存档凭据；数据库配置可选，未配置时使用 SQLite。HTTP 客户端和代理配置只属于 `CustomerContactDirectory` 的 REST API 边界。
