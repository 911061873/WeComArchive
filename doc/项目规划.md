# WeComArchive 第一版项目规划

确认日期：2026-09-28。

本文是本次需求梳理后唯一有效的项目规划，替代此前的消息获取、客户信息维护和任务管理规划。本文描述目标行为，不代表现有代码已经实现。项目处于开发阶段，允许完全重构，不要求兼容现有接口与目录结构。

## 1. 目标与使用者

面向初级开发者提供 Python 依赖包。开发者在自己的项目中引入、配置并启动框架，实现企业微信会话存档消息的自动获取、解密、数据库保存，以及按规则触发异步消费。

开发者自行实现业务消费逻辑。典型场景是通过 HTTP 将消息推送到影刀控制台队列，框架提供示例，不内置该业务集成。

## 2. 技术栈与配置

- Python 3.10+。
- 使用 pyweworkfinance 轮询获取消息。
- SQLAlchemy 2.x ORM、Alembic 数据库迁移、Pydantic 2.x 配置与数据模型。
- 未传数据库连接字符串时使用 SQLite；传入时使用指定数据库。第一版支持并验证 SQLite、MySQL 和 PostgreSQL。
- 单企业接入，不设计多企业管理。
- 使用 Pydantic 配置对象，通过 Python 代码注册规则和消费者；配置修改后重启生效。
- 首次运行自动建表，后续数据库结构升级通过显式调用 Python 迁移 API 执行。

## 3. 消息采集、游标与事务

流程：轮询获取 → 解密与类型处理 → 消息和游标事务提交 → 时间窗口检查 → 正文规则匹配 → 异步消费队列。

- 第一次获取传入消息游标 0，后续使用数据库中持久化的消息游标。
- 原始加密消息成功入库即可推进对应游标，不要求所有消息解密成功。
- 每批消息存储与游标更新在同一数据库事务中提交；数据库保存失败则回滚，不推进游标。
- 获取失败记录日志，不更新游标，不增加单独重试机制，等待下次轮询。
- 部分消息解密失败时，保留加密消息并记录日志，不重试，不阻塞其他消息和游标推进。
- 消息按唯一标识去重，重复拉取不重复入库、不再次触发消费。
- 仅在数据库事务提交成功后触发消费。

## 4. 消息存储

分别保存以下数据：

1. 加密消息表：所有获取到的原始加密消息，包括解密成功和失败的消息。
2. 解密消息表：解密成功消息的完整数据。
3. 消息类型分表：根据已实现的类型处理能力，提取并保存对应类型字段。

尚未支持的消息类型仍保存加密消息和完整解密数据，只跳过类型分表。已支持类型解析失败时，同样保留基础数据并记录日志。具体类型清单在检查现有代码后确定。

不自动下载图片、语音、视频、文件等附件。

## 5. 时间窗口与规则

- 消费时间窗口可配置，默认 5 分钟，以消息自身的发送时间判断。
- 所有获取到的消息均按存储规则存档，时间窗口只影响消费。
- 在入库后准备分发时检查时间窗口；进入队列后不因排队导致超出窗口而丢弃。
- 正常轮询与重启后的补拉使用同一时间窗口规则。
- 支持关闭时间限制，允许所有新拉取入库的消息参与消费；不自动重放数据库中已有消息。
- 第一版仅匹配文本消息的内容。
- 每条规则选择“包含指定文本”或“正则匹配”，二选一。
- 每条规则绑定一个消费者。消息命中多条规则时分别处理，即使绑定同一个消费者也执行多次。
- 保留后续扩展“消息发送者”过滤条件的空间，第一版不实现。

消息去重与规则分发是不同层次：重复拉取不重复分发，但同一新消息的多个规则命中均独立分发。

## 6. 异步消费与生命周期

- 开发者直接传入同步 def consume(message) 或异步 async def consume(message) 函数，接收 Pydantic 消息对象。
- 同步消费者在线程池中执行，避免阻塞事件循环；关闭超时不能中断已开始执行的同步函数，其业务副作用可能继续，asyncio.run() 会等待默认线程池退出，同步 I/O 需自行设置超时。
- 使用进程内有界队列，配置队列容量和异步工作任务数。
- 队列满时等待，对上游施加背压，避免无限积压内存。
- 并发时不保证消费完成顺序；工作任务数设为 1 时串行执行。
- 消费失败记录日志，不自动重试，继续处理后续任务。
- 正常关闭时停止拉取，等待队列任务完成，并设置最长等待时间。
- 强制退出或超过关闭等待时间后，未完成的消费不在重启时恢复。
- 已入库但未分发或未完成消费的消息不自动重放。因此不承诺消费必达或业务副作用恰好执行一次。

## 7. 第一版范围之外

- 多企业管理。
- 附件自动下载。
- 客户、客户群和关系维护，以及对应回调与同步服务。
- 管理页面、规则热更新、独立配置文件格式。
- Redis 或其他外部消息队列。
- 持久化消费任务恢复、历史消息重放、失败自动补偿。
- 内置影刀业务消费者；仅提供开发示例。

## 8. 交付内容

- 可安装的 Python 依赖包。
- 快速入门与配置说明。
- 完整运行示例。
- 开发者自定义异步消费者与影刀 HTTP 推送示例。
- Alembic 迁移支持及升级说明。
- 核心流程测试与 SQLite、MySQL、PostgreSQL 兼容性验证。

## 9. 验收标准

1. 未指定连接字符串可使用 SQLite；指定 MySQL 或 PostgreSQL 时完成相同核心流程。
2. 首次游标为 0，成功存储后持久化推进；重启后从保存位置继续获取。
3. 获取或数据库提交失败不推进游标；部分解密失败保留密文、记录日志并允许整批成功提交。
4. 成功解密消息同时保留密文与完整明文，已支持类型进入分表；未知类型或解析失败不丢失基础数据。
5. 重复消息不重复入库或再次消费。
6. 仅文本正文参与包含文本或正则匹配，每个规则命中独立触发绑定消费者。
7. 默认 5 分钟时间窗口只限制消费，不限制存档；可修改或关闭，不重放已入库消息。
8. 队列容量与并发数可配置，队列满时等待，消费者异常不终止其他任务。
9. 正常关闭限时等待，重启不恢复未完成消费。
10. 首次可自动建表，后续可通过显式调用 Python 迁移 API 升级数据库结构。
