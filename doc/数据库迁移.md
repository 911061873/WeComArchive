# 数据库迁移

第二版 schema 版本为 `0002`，由 Alembic 管理。空库构造时自动安装最新结构；已有库版本不匹配则抛出错误。
同一数据库只能运行一个主服务实例，执行升级前先停止服务并备份数据库。

```python
from wecomarchive.db import Database
from wecomarchive.migration import upgrade

db = Database("sqlite:///./wecom_archive.db")
try:
    upgrade(db.engine)
finally:
    db.dispose()
```

`0001` → `0002` 保留游标、密文、明文和历史类型表，增加密钥版本、独立阶段状态、统一消息表和消费者任务表。
已解密的密文标为 success，第一版解密错误保留 failed；历史解析错误保留 failed，其余历史明文进入 pending 供第二版解析。
第一版只保留解析后的 JSON，迁移重新序列化为 raw_text，无法恢复原始空白；第二版新消息保存 SDK 原始明文。
第一版没有消费者成功/失败记录，无法还原这些历史结果；升级后仍在消费窗口内的消息可能再次消费，业务需自行保证幂等。

不受 Alembic 管理的开发旧库拒绝自动升级，请备份后另建空库。拒绝从第二版有损降级，回到第一版需恢复备份。
第二版保留第一版 archive_type_* 历史表，但当前仅生成统一文本消息，不再写入历史类型表。

解密状态在 archive_encrypted.status，解析状态在 archive_decrypted.status，消费者状态在 archive_consumer_task.status。
新增类型支持后需要人工将 unsupported 的解析任务改为 pending；failed 不会在重启时自动恢复。
启动会恢复 processing 状态，并恢复已配置密钥版本的 waiting_key 消息。
