# 数据库初始化与升级

首次运行连接空库时自动执行随包发布的 Alembic 初始版本，建立全部消息表及版本记录。
现有库启动时只检查版本，不调用 create_all 补表、不自动执行升级。
这种组织保证新安装和后续显式升级使用同一迁移历史。

## 显式命令

先停止采集服务并备份数据库，然后安装新版本的包并执行：

```shell
wecomarchive-db current --database-url "sqlite:///./wecom_archive.db"
wecomarchive-db upgrade --database-url "sqlite:///./wecom_archive.db"
```

也可使用 `python -m wecomarchive.cli upgrade`。URL 默认取 `WECOM_DATABASE_URL`，
未设置时使用当前目录的 `wecom_archive.db`。数据库密码不便写在命令行时使用环境变量。
迁移命令不需要企业微信凭据或私钥，不创建 SDK。

当前初始版本为 `0001`。upgrade 可重复执行；已有库结构版本不等于当前包 head 时，服务拒绝启动并提示升级。
MySQL DDL 不具备完整事务回滚能力；迁移中断时先检查结构与备份，不要直接 stamp 掩盖不完整迁移。

## 旧开发库

旧版 progress、encrypted_message、decrypted_message、attachment、message_consumption
不属于新版本结构。当前规划允许不兼容重构，**不自动转换、清空或覆盖旧库**。
请保留备份并为新框架指定空库或新的 SQLite 文件。新库从游标 0 开始，受企业微信可拉取历史范围限制；
新库默认仍只消费最近 5 分钟。旧历史数据保留在原库，框架没有历史回放入口。

检测到非空且没有 Alembic 版本的数据库时，启动和 upgrade 都拒绝继续。
业务应用已有其他表时，首版也要求为本框架提供独立空库，避免误认未受版本管理的结构。

## 开发新的迁移

迁移文件位于 `src/wecomarchive/migrations/versions/`，随 wheel 一起发布。
使用 Nuitka 构建时，迁移目录不参与编译；`setup.py` 在编译后的 wheel 安装暂存步骤中
复制迁移 `.py` 源文件，供 Alembic 按文件路径加载。仅配置 `package-data` 不够，
因为 Nuitka 会在编译后清理构建目录中的 Python 源文件。
新增版本设置唯一 revision 和前一版本 down_revision，用 Alembic `op` 明确升级/降级步骤；
不得修改已发布迁移、不得从迁移脚本导入会变化的运行时 ORM 模型。
更新模型后用空库初始化测试以及旧版本升级测试，确认 Alembic `compare_metadata` 与 ORM 无差异。

迁移机制参考 [Alembic 官方教程](https://alembic.sqlalchemy.org/en/latest/tutorial.html)。
