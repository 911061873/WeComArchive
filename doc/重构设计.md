# 第二版重构设计

以 [第二版规划](第二版规划.md) 为准。第一版规则分发与进程内队列已由数据库持久化流水线取代。

## 入口与资源

`wecomarchive.main.WeComArchive` 构造时校验配置、获取数据库实例锁、初始化数据库和 SDK、创建四个子服务。
`set_private_key(pem, version)` 和 `add_consumer(name, match_text, is_regex, callback)` 只允许在启动前调用。
`start()` 主线程阻塞运行，接管 Ctrl+C/SIGTERM，停止完成后恢复信号处理器。没有公共 stop。
构造失败清理已初始化资源；未启动实例支持 close 与上下文管理。

## 服务边界

`services/base.py` 抽象基类统一管理线程、停止事件、领取闸门、轮询等待和在途计数。
四个服务共享停止闸门，领取与停止快照互斥，避免停止后继续领取任务。

| 服务 | 工作 | 成功后的数据 |
| --- | --- | --- |
| pull | 单线程按已保存游标拉取，失败下轮继续 | 密文及游标同事务提交 |
| decrypt | 按密钥版本解密，不解析 JSON | 原始明文字符串 |
| parse | Pydantic 校验文本公共字段及内容 | 统一 ConsumerMessage |
| consume | 按稳定名称调用同步/异步消费者 | 每个消息 × 消费者的独立终态 |

公共字段包含消息 ID、序号、类型、毫秒发送时间、发送者、接收者、群 ID、动作；data 保留完整原始对象。
当前支持字典仅包含 text，未知及媒体类型标记 unsupported。附件下载留待媒体解析实现。

## 持久化与并发

`ArchiveStore` 串行执行短数据库事务，事务外执行 SDK、解析和用户业务。
任务领取先将 pending 改为 processing 并提交，单实例多线程不会重复领取。
SQLite 文件锁、MySQL 会话锁和 PostgreSQL advisory lock 阻止第二个主服务实例。
原生 SDK 共享句柄调用另外加锁，不假设其线程安全。

解密缺少密钥进入 waiting_key，配置了对应版本的历史消息在启动时恢复。
其他失败任务不自动重试。每次启动只将 processing 恢复为 pending，表示上次进程被中断的任务。
消费者状态复合主键为消息 ID 和名称，新增消费者独立检查消费资格。

消费窗口默认 300 秒，在领取和准备调用前检查；已开始调用不因窗口变化而中断。
退出只统计停止领取时仍在执行的任务，消费按调用次数统计；未领取任务保留到下一次启动。
主服务等待所有工作线程结束后关闭 SDK 和数据库，无强制消费取消或关闭超时。

## 数据库表

| 表 | 内容 |
| --- | --- |
| archive_progress | 持久化拉取游标 |
| archive_encrypted | 密文、密钥版本、解密状态及错误 |
| archive_decrypted | 原始明文、解析状态及错误，保留第一版兼容列 |
| archive_parsed | 统一消息 JSON 及发送时间索引 |
| archive_consumer_task | 消息 × 消费者的状态及错误 |

第一版 archive_type_* 表在迁移中保留，但第二版不写入这些历史类型表。
已完成业务但未提交成功状态时进程退出会造成重复消费，业务自行保证幂等。

注册消费者时提供名称、匹配文本、是否正则及处理函数。普通文本使用子串匹配，正则使用 search 并在注册时编译。
未命中条件的调用标记 skipped，不执行处理函数，重启后保留该状态。空匹配文本表示匹配所有文本消息。
