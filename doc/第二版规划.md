# 第二版规划

本规划记录本轮确认的重构要求，忽略历史规划。公共字段在数据建模阶段进一步确定。

## 使用入口

`main` 中的主服务类作为用户使用入口。用户通过构造函数传入参数，完成配置校验、公共资源初始化和四个子服务的创建。构造失败时抛出错误。

主服务提供解密密钥设置方法和消费者注册方法。密钥与消费者必须在开始运行前配置完成，运行期间不允许调整。

主服务统一管理四个子服务的启动、停止和资源释放。主服务的 `start()` 阻塞运行，不提供公共 `stop()` 方法；子服务的 `start()` 立即返回。停止后整个服务退出。

## 服务模块

`services` 目录包含服务基类和四个具体服务。

### base：服务基类

定义抽象类，接收线程数、轮询间隔等公共参数。参数由各服务分别配置，拉取服务固定单线程。

基类负责启动、停止、停止状态检查和轮询等待等通用运行控制。各具体服务实现自己的任务获取及处理逻辑。

### pull：拉取服务

调用企业微信会话内容存档接口，按游标拉取加密消息并保存到数据库。

消息保存成功后推进拉取游标。消息保存与游标推进在同一数据库事务中完成。

拉取或保存失败时保留原游标并记录错误，允许下一轮继续拉取。每次拉取均使用最新的已保存游标。拉取轮询与其他阶段失败任务不自动重试的规则分别处理。

### decrypt：解密服务

获取待解密消息，根据密钥版本选择对应私钥，调用 SDK 解密，并保存解密后的原始明文内容。

该服务只负责解密，消息内容的结构解析由解析服务处理。

缺少对应版本密钥的消息进入独立的等待状态，不视为解密失败。

服务启动时，将此前因缺少密钥而等待、且当前已配置对应版本密钥的消息恢复为待解密，执行一次历史补解密。仍缺少密钥的消息保持等待状态。

解密失败的消息标记失败，不自动重试；重启后也不恢复这些失败任务。不考虑运行期间设置或更新密钥。

### parse：解析服务

获取待解析的明文消息，根据消息类型解析内容，生成统一消息对象，供消费服务使用。

当前只支持文本消息。创建支持的消息类型字典及对应的 Pydantic 数据模型。公共字段在数据建模阶段具体确定。

未知或当前未支持的消息类型不做解析，标记为“暂不支持”，后续启动不自动重新解析。新增对应类型支持后，由用户手动操作数据库，将状态重置为“待解析”，再由解析服务处理。

附件下载属于含有媒体的消息解析过程。当前先建立解析流程，未来实现媒体消息解析时，再加入附件下载及相关处理逻辑。

解析失败的消息标记失败，不自动重试。

### consume：消费服务

获取解析完成的消息，调用用户注册的消费者，执行用户定义的业务逻辑。

通过方法注册多个消费者。注册时传入唯一且跨重启稳定的消费者名称、内容匹配文本、是否正则及处理函数，分别持久化各消费者的处理状态。

普通匹配检查文本内容是否包含匹配文本，正则匹配使用 search，并在注册时校验及编译。仅命中条件才执行处理函数；未命中标记为跳过，重启不重复检查。空匹配文本匹配所有文本消息。

同时支持同步和异步函数，在注册阶段识别函数类型，避免每次消费调用时重复识别。消费者不要求按顺序执行。

消费者正常返回时标记消费成功，抛出异常时标记消费失败。一个消费者失败不影响其他消费者继续处理同一条消息。消费失败不自动重试，重启后也不重试。

支持消息时间窗口配置，默认 5 分钟。以消息自身时间为依据，只消费当前时间最近 5 分钟内的消息。在准备调用消费者时检查窗口；已经开始执行的调用不因消息超出窗口而中断。

新增消费者不补消费窗口之外的历史消息，只处理窗口内且该消费者尚未处理、尚未失败的消息。其他消费者的处理状态不影响当前消费者的处理资格。超出窗口的消息保留解析结果，但不再消费。

接受以下重复消费风险：消费者已完成业务操作，但进程在保存消费成功状态之前退出，重启后可能再次执行该消费者。在 README 中说明该风险，提醒用户按业务需要自行保证幂等。

## 处理流程与持久化状态

**拉取加密消息 → 解密得到原始明文 → 解析消息内容 → 交给消费者处理**

各阶段通过持久化状态衔接。同一数据库只允许一个主服务实例运行。

单个解密、解析或消费任务失败后，记录失败状态并终止该任务，不自动重试，其他任务继续处理。服务重启后保留失败状态。

每次启动时，将解密、解析及各消费者任务的“处理中”状态恢复为“未处理”。成功、失败、缺少密钥和暂不支持等其他状态保持不变；缺少密钥的历史消息按解密服务启动规则单独处理。

多线程领取任务时，应避免同一任务被同时领取和执行。

## 停止与退出进度

主服务监听 Ctrl+C。收到信号后，所有子服务停止领取新任务，等待正在执行的任务完成，再释放资源并退出。

停止期间显示当前剩余任务的处理进度，按服务显示剩余数量，并显示总体完成数量与总数量。

统计范围为停止领取任务后仍在执行的任务，成功与失败都计为任务已结束。消费阶段按“消息 × 消费者”的调用次数计数。

数据库中尚未领取的任务不计入退出进度，留待下次启动处理。

示例：

```text
正在停止，等待剩余任务完成……
解密：剩余 2
解析：剩余 1
消费：剩余 3
退出进度：4/10，剩余 6
```

同步消费者无法通用地强制取消，耗时调用可能延迟退出，服务等待其结束。
